    - peek_mut allows putting the binary heap in a bad state
    - david's fix changes the heap size to 1 while the PeekMut is alive. (forgetting the PeekMut would leave it at size 1)
    - seems like a good solution
    - this is the only stable way to break the heap structure.
    - there are two unstable methods that could also allow breaking the structure, though.
      - retain() with &T seems fine. Would be a problem with &mut T though.
    - We should document that `BinaryHeap<u32>` (etc.) are guaranteed to be in proper heap order.
    - FCP merge let's go.
