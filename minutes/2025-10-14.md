The 8472: That goes back to the RFC argument that it might unexpectedly fail on some platform if the layout doesn't match. Assuming you're talking about having different input and output types. So if someone just slaps an expect on it, it compiles on 64 platforms and blow up on 32.

Amanieu: So have I.

The 8472: I think there's not much of an argument we don't want this. We said before this is useful. Just having this foolproof in the standard library is ..

Amanieu: It still feels like the specific use case is into storage / from storage. But that doesn't help with the lifetime issue.

The 8472: Yeah we have to store the alignment, because the allocater is alignment sensitive so we need to keep track of that. And as soon as we allow a different input and output type we run into platform dependence.

The 8472: yeah.
